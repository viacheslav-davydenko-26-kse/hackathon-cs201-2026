# «ДеЦе? Live» — план реалізації (хакатон OpenData, 3,5 год, 5 людей)

## Контекст
Базова «GeoGuessr по даних» (показати факти → вибрати область зі списку) робиться за ~1,5 год і не дає вау-моменту. Нам потрібна одна цілісна, масштабніша ідея, де відкриті дані — ядро механіки, з трьома рівнями (MVP 1:30 / Core 2:30 / Stretch), кожен з яких сам по собі є робочим демо.

---

## 1. Фінальна ідея

**Назва:** «ДеЦе? Live».

**Одним реченням:** квіз-шоу в стилі Kahoot на відкритих даних: журі сканує QR, з телефонів тапає по карті України, вгадуючи область за фактами, які система сама згенерувала з 5 державних датасетів. Після кожного раунду на великому екрані з'являється «теплова карта» відповідей усієї зали і картка області з графіками «чому саме ці цифри».

**Чому саме така комбінація (і що відкинуто):**
- **SVG-карта + «гаряче/холодно»** беремо. Без цього це звичайний тест, а не «GeoGuessr».
- **Прогресивні підказки + генерація фактів** беремо, і це серце проєкту. Дані тут не для галочки: факти (ранги, відхилення від середнього, категоріальні) рахуються з даних, а підбір підказок *гарантує*, що раунд має рівно одну правильну відповідь. Це сильна теза для журі.
- **Мультиплеєр через QR** беремо в Core. Тут вау-момент: журі грає саме, а не дивиться на нас.
- **Картка області** беремо в Core. Вона закриває пункт «дані в центрі»: показує джерела, порівняння із середнім по Україні, графіки.
- **Щоденний челендж, режим навпаки, LLM-загадки** йдуть у Stretch. Вони не додають вау на 2-хвилинному демо, а розпорошують команду.

**Рівні (кожен є окремим робочим демо):**

| Рівень | Дедлайн | Що працює |
|---|---|---|
| MVP | 1:30 | Соло-гра в браузері: карта України (d3-geo), 5 прогресивних підказок, згенерованих із реальних даних; до 3 спроб із підсвіткою «гаряче/холодно» за відстанню; бали; короткий екран результату |
| Core | 2:30 | Кімнати: `host.html` на проєкторі з QR, `play.html` на телефонах (REST-polling раз на 1 с). Підказки відкриваються за таймером, живий лідерборд. Після раунду: розподіл відповідей зали на карті, лінії «відповідь → правильна», картка області з Chart.js |
| Stretch | 3:00 | LLM-загадки (попередньо згенеровані й закешовані в БД), «поділитися результатом» емодзі-сіткою, щоденний челендж, режим «Справжнє чи фейк?» |

**Сценарій демо (120 с).** До старту кімната вже створена, QR на проєкторі. Ведучий: Вадім, за ноутбуком Слава.

| Секунди | Що відбувається на екрані | Що говорить ведучий |
|---|---|---|
| 0–10 | Великий QR + «Приєднуйтесь» | «Наскільки добре ви знаєте свою країну в цифрах? Скануйте, зараз гратимемо разом» |
| 10–25 | В лобі живо з'являються імена гравців | «Ми зібрали 5 відкритих датасетів: тривоги, ДРАЦС, реєстрації авто МВС, НМТ, населення. Це N мільйонів рядків» |
| 25–55 | Раунд 1. Підказка 1 (найважча), через 7 с підказка 2, потім 3. Лічильник «відповіли 4/6» | «Перша підказка найменш очевидна, кожна наступна дає менше балів» |
| 55–75 | Розкриття: карта зафарбована за кількістю відповідей, лінії від кожної відповіді до правильної, бали, лідерборд | «Ось де шукала зала. Червоні гарячі, сині холодні» |
| 75–100 | Картка області: 4 бари «область vs середнє по Україні», графік тривог за місяцями, джерела | «Кожен факт рахується з даних автоматично, ми не писали їх руками. І система гарантує, що підказки дають рівно одну правильну відповідь» |
| 100–120 | Фінальний лідерборд + слайд-підсумок у футері host-екрана | «2 400 фактів, 25 регіонів, 5 джерел, Python + FastAPI. Код на GitHub. Дякуємо!» |

Демо-режим: `DEMO_ROUND_SECONDS=30` і 1 раунд (env-змінна). Ще 2 телефони команди підключені як резервні гравці на випадок, якщо журі не встигне приєднатися.

**Ризики даних і рішення:**
- **Різні назви та коди.** Коди КОАТУУ/КАТОТТГ і ISO 3166-2 *не збігаються* для кількох регіонів: Київ 80 vs UA-30, Чернівецька 73 vs UA-77, Луганська 44 vs UA-09, Крим 01 vs UA-43, Севастополь 85 vs UA-40. Тому PK — наш slug (`lviv`, `kyiv_city`, `kyiv_obl`), а `koatuu2` та `iso` зберігаються окремими колонками. Нормалізатор прибирає «область», «обл.», «м.», приводить апострофи `’ ' ʼ` до одного вигляду, замінює латинську `i` на кириличну `і`, робить lower(). Окрема таблиця аліасів містить англійські назви з GeoJSON.
- **Київ.** Окремий регіон від Київської області скрізь (тривоги, ДРАЦС, МВС, НМТ це розрізняють). На карті він крихітний, тому поверх нього ставимо клікабельне коло r=10px.
- **Окуповані/прифронтові.** НМТ і ДРАЦС по Луганській, частково Донецькій та Херсонській неповні. У Луганській області тривога майже постійна, і метрика «кількість тривог» там вироджується. Правило таке: регіон з NaN по метриці просто не отримує факту з цієї метрики, а ранги рахуємо серед регіонів, де дані є («3-я з 22»). `etl/check.py` перевіряє, що кожен ігровий регіон має ≥ 8 фактів. Якщо в регіону їх менше, він стає неігровим (Луганську, ймовірно, доведеться так і позначити, і це варто чесно сказати на демо).
- **Тривоги дублюються** на рівнях область/район/громада: для метрик області беремо лише `level == 'oblast'`.
- **Населення 2022** не враховує ВПО, тому в картці підписуємо «на 1000 мешканців (станом на 01.01.2022)».
- **Розмір файлу МВС**: читаємо через DuckDB (`read_csv_auto`, тільки потрібні колонки), а не через pandas.

## 3. Єдиний формат даних (контракт)

### Схема SQLite (`db/schema.sql`)
```sql
CREATE TABLE regions (
  id TEXT PRIMARY KEY,          -- 'lviv', 'kyiv_city'
  name_uk TEXT NOT NULL,        -- 'Львівська область'
  short_uk TEXT NOT NULL,       -- 'Львівщина'
  iso TEXT, koatuu2 TEXT,
  playable INTEGER NOT NULL,    -- 0 для Криму/Севастополя (і, можливо, Луганської)
  lat REAL, lon REAL,           -- центроїд
  population INTEGER, area_km2 REAL
);
CREATE TABLE region_aliases (alias TEXT PRIMARY KEY, region_id TEXT REFERENCES regions(id));
CREATE TABLE metrics (
  id TEXT PRIMARY KEY,          -- 'alerts_hours', 'cars_top_brand'
  title_uk TEXT, unit TEXT,     -- 'годин тривоги', 'на 1000 мешканців'
  kind TEXT,                    -- 'numeric' | 'categorical'
  category TEXT,                -- 'war' | 'demography' | 'cars' | 'education'
  source_name TEXT, source_url TEXT, year INTEGER
);
CREATE TABLE region_metrics (
  region_id TEXT, metric_id TEXT,
  value REAL, value_text TEXT,  -- value_text для categorical ('Renault')
  rank INTEGER, n_ranked INTEGER,
  PRIMARY KEY (region_id, metric_id)
);
CREATE TABLE series (region_id TEXT, metric_id TEXT, period TEXT, value REAL); -- '2024-03'
CREATE TABLE facts (
  id INTEGER PRIMARY KEY,
  region_id TEXT, metric_id TEXT,
  kind TEXT,                    -- 'rank' | 'relative' | 'raw' | 'categorical'
  text_uk TEXT,                 -- 'У топ-3 областей за годинами тривоги'
  consistent TEXT,              -- JSON-список регіонів, для яких це твердження теж істинне
  info REAL,                    -- log2(25 / len(consistent)), тобто наскільки факт видає відповідь
  riddle_uk TEXT                -- Stretch: LLM-перефразування
);
CREATE TABLE scores (id INTEGER PRIMARY KEY, nickname TEXT, mode TEXT, points INTEGER,
                     daily_date TEXT, created_at TEXT); -- Stretch
```

### Генерація фактів і підбір підказок (ключова логіка)
- Для кожної пари (регіон, numeric-метрика) створюємо факти трьох видів: **rank** (топ-1/топ-3/останні-3), **relative** («на 23% нижче за середнє по Україні», бакети ±10%), **raw** («412 годин тривоги за 2024»). Для categorical-метрик: «найпопулярніша марка нових авто — Renault».
- `consistent` — множина регіонів, для яких це твердження теж істинне (для relative: регіони з того ж бакета; для categorical: ті, де значення таке саме).
- `pick_hints(region_id, n=5)`: жадібно беремо факти з **різних категорій**, сортуємо за зростанням `info` (спочатку найважчий) і перевіряємо, що перетин `consistent` усіх 5 фактів дорівнює `{region_id}`. Так раунд гарантовано має одну відповідь.

### Бали
- `HINT_MULT = [1.0, 0.8, 0.6, 0.45, 0.3]` за індексом останньої відкритої підказки.
- Правильна відповідь: `1000 * mult`. Неправильна: `500 * mult * max(0, 1 - d_km/500)`. Соло: до 3 спроб, кожна наступна ×0.5.
- Мультиплеєр: +до 100 балів швидкості пропорційно часу, що лишився.
- «Гаряче/холодно» (haversine між центроїдами): `<150 км` червоний `hot`, `<300` помаранчевий `warm`, `<500` жовтий `cool`, далі синій `cold`.

### REST API (`app/schemas.py`, pydantic; копія в `docs/contract.md`)
```
GET  /api/regions                    -> [{id, name_uk, short_uk, playable, lat, lon}]
GET  /static/ua.geojson              -> FeatureCollection, properties.region_id = наш slug
POST /api/solo/rounds                -> {round_id, total_hints: 5, hints: [Hint]}       # перша підказка
POST /api/solo/rounds/{id}/hint      -> {hints: [Hint]}                                   # усі відкриті
POST /api/solo/rounds/{id}/guess     body {region_id}
                                     -> {correct, attempt, attempts_left, distance_km,
                                         heat: "hot|warm|cool|cold", points,
                                         answer_region_id: str|null}   # null, поки є спроби і не вгадано
GET  /api/regions/{id}/card          -> Card
POST /api/rooms                      -> {code: "K7QF", host_key, join_url, qr_svg}
```
```json
Hint = {"index": 0, "text": "Тут найпопулярніший колір нових авто — сірий", "metric_id": "cars_top_color", "category": "cars"}
Card = {
  "region": {"id": "lviv", "name_uk": "Львівська область"},
  "metrics": [{"metric_id":"births_per_1000","title_uk":"Народжуваність","unit":"на 1000",
               "value":6.1,"ukraine_avg":5.0,"rank":2,"n_ranked":23,
               "source_name":"Мін'юст, ДРАЦС","source_url":"https://data.gov.ua/..."}],

}
```

### Кімнати: REST + polling
Host і гравці опитують `GET .../state` раз на 1 с, дії йдуть звичайними `POST`.
```
POST /api/rooms/{code}/players       body {name}                -> {player_id}
POST /api/rooms/{code}/start         body {host_key}            -> RoomState
POST /api/rooms/{code}/next          body {host_key}            -> RoomState   # наступний раунд
POST /api/rooms/{code}/guess         body {player_id, region_id} -> {region_id}
GET  /api/rooms/{code}/state?player_id=...                      -> RoomState
```
```
RoomState = {code, status: "lobby|round|reveal|finished",
             players: [{id, name, score}],
             round_no, total_rounds, ends_at,      # null у lobby
             hints: [Hint],                        # усі відкриті на зараз
             answered: 4, total: 6,
             my_guess: str|null,                   # якщо передано player_id
             reveal: {answer_region_id, guesses:[{player_id,name,region_id,distance_km,heat,points}],
                      distribution:{"lviv":3,"volyn":1}, card: Card} | null,
             leaderboard: [{name, score}]}
```
`RoomManager` у `app/game/rooms.py` — чистий Python без залежностей від транспорту. Фонового таймера нема: відкриті підказки й кінець раунду рахуються з `started_at` при кожному запиті (`ROUND_SECONDS/5` с на підказку; раунд закінчується, коли всі відповіли або минув час).

**Моки:** `static/mock/*.json` (по одному файлу на кожну відповідь вище). У `static/js/api.js` є прапорець `const USE_MOCK = true`, тож фронт працює з першої хвилини.

## 5. Розподіл задач і таймлайн

### Аналіз навантаження → роль Матвія
Якщо розкласти ідею на потоки, вузьких місць три:
1. **Дані → факти** (критичний шлях MVP). Без фактів нема гри. У початковому розподілі Ілля мав і чистити 5 джерел, і генерувати факти. Це найбільший ризик не встигнути до 1:30, бо ETL кривих CSV завжди з'їдає вдвічі більше часу.
2. **Слава** одночасно робить API, ігрову логіку, кімнати, інтеграцію і git. Якщо на ньому ще й логіка фактів/підказок, Core не злетить.
3. **Фронт**: 3 екрани + карта на одного Андрія.

**Рішення: Матвій бере «рушій фактів» під ключ** (`metrics_catalog.py`, `build_facts.py`, `game/hints.py`, баланс балів), а після MVP веде вертикальний зріз «картка області» (`game/card.py` + `js/card.js`). Чому саме так:
- Це місце, де відкриті дані стають геймплеєм, тобто головна теза для журі. Їй потрібен окремий власник, а не «хто встигне».
- Інтерфейси чисті: на вході таблиця `region_metrics`, на виході `facts` + функція `pick_hints()`. Матвій стартує з 0:00 на фейковому `region_metrics` (CSV руками на 25 регіонів) і нікого не блокує.
- Ілля розвантажується до «сире → `region_metrics`». Слава розвантажується від ігрового контенту і встигає кімнати.
- Другий фронтендер дав би менше: карта і екрани добре діляться між Андрієм і Вадімом (`play.html`), а картку бере Матвій.

Вадім знімає ризик №1 на старті простими ETL (`build_geo`, населення), потім відповідає за демо і `play.html`, бо він однаково тестуватиме на телефонах. З 2:30 він же робить QA.

## 7. Лінії відсічення

**Викидаємо першим, якщо відстаємо (за порядком):**
1. Весь Stretch (LLM-загадки, щоденний челендж, «навпаки», емодзі-сітка).
2. Лінії на reveal: лишаємо тільки хороплет розподілу.
3. Графік серії в картці: лишаємо бари vs середнє.
4. НМТ: вистачає 4 датасетів, ≥ 8 фактів на регіон перевіряє `check.py`.
5. Таймер підказок у кімнаті: хост сам тисне «Наступна підказка».
6. Якщо мультиплеєр не працює зовсім, демо йде на соло-MVP + картці, а журі пропонуємо назвати область вголос.

**Додаємо, якщо випереджаємо:** LLM-загадки (готуються офлайн, на демо нуль латентності) → емодзі-сітка «поділитися» → щоденний челендж (seed = дата, таблиця `scores`) → режим «Справжнє чи фейк?» (показуємо область і 3 числа, одне з них справжнє).

## 8. Ризики і план Б

| Ризик | Ознака | План Б |
|---|---|---|
| Wi-Fi площадки ізолює клієнти або блокує порти | Телефони не відкривають LAN-IP | Основний варіант — `cloudflared tunnel --url http://localhost:8000` (без interstitial-сторінки, як у ngrok free). Резерв — роздача з телефона команди. Ще один резерв — деплой на Render/Fly о 2:30 |
| Тунель упав під час демо | QR не відкривається | Резервні гравці — телефони команди в хотспоті. Крайній випадок — записане відео |
| ETL файлу МВС повільний/кривий | > 20 хв на `load_cars` | DuckDB + лише 1 місяць даних. Якщо не виходить, метрики авто викидаємо (дані без них все одно гра) |
| Назви регіонів не зводяться | `normalize_region` кидає KeyError | Сувора помилка з виводом сирої назви, Ілля додає аліас. Перевірка всіх джерел іде першою задачею о 0:15 |
| Підказки не дають однозначної відповіді для якогось регіону | `test_hints.py` червоний | Додати факт із categorical-метрики. Якщо не допомагає, регіон `playable=0` |
| Хтось не встигає | На чекпоінті нема мерджу | На 1:30 Матвій (факти готові) підстраховує Іллю. На 2:30 Вадім кидає `play.html` в Андрія і йде в QA. Слава вирішує на кожному чекпоінті |
| LLM-ключі / ліміти | `gen_riddles` падає | Stretch, тому не критично. Загадки генеруються лише офлайн, на демо живих LLM-викликів нема |
| Конфлікти git | Мердж > 5 хв | Таблиця володіння файлами. Хто порушив, той і розв'язує |
